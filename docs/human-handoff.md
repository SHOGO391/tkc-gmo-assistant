# Computer Useによる計上と人への引継ぎ

2026-10-09の要望に基づく導入目標は、GMO明細から取引先の照合・新規先登録・仕訳の取込みと計上・結果確認まで進め、判断できない箇所を人が引き継ぐ運用です。**現在の実装はローカルのプレビューと引継ぎ管理までです。TKCへの自動入力・取込・計上はまだ実行できません。**

## 現在使える機能

1. `npm run dev` またはビルド後の `npm start` で起動し、ジョブを開きます。
2. 「人への引継ぎ」を開くと、未接続、未特定の取引先、未確認の仕訳、不正行、重複の判断、新規登録案、保存結果不明を表示します。
3. 各項目に、止まった理由、原本のファイル・物理行・SHA-256、登録状態、仕訳状態、最後に確認できた段階、確認項目、再開条件を表示します。同じ法人の登録案は関連する明細をまとめます。
4. 「担当・回答を記録」で担当者・記録者・回答状態・内容・根拠を保存します。中断中も記録できます。「回答あり」には根拠が必須です。
5. 「引継ぎCSV」「詳細JSON」でこのPCへ出力できます。アプリが人へのメール送信や外部サービスへのアップロードをすることはありません。
6. 回答をもとに元の明細画面で取引先・証憑・ルールを確認します。回答を記録しただけでは、承認、登録完了、計上完了になりません。内容が変わった回答は再確認待ちにし、古い内容への回答は拒否します。過去の回答はJSONと操作履歴に保持します。

CSVは引継ぎ用です。TKCの取込形式としては使えません。CSVには原本位置・確認項目・回答を、JSONには明細の金額・摘要・銀行ID・仕訳案・登録案・履歴も含めます。業務情報が含まれるためローカルで管理してください。再送許可は全項目で `false` です。

CLIでも出力できます。`JOB_ID` は実際のジョブIDへ置き換え、出力先は存在しない新しいファイルを指定します。

```powershell
npm run cli -- handoff_job JOB_ID
npm run cli -- export_handoff JOB_ID private/human-handoff.csv
```

出力先のフォルダは事前に作成します。既存ファイルは上書きしません。`private/` はGit対象外です。Web APIはジョブの `/handoff` をGETして詳細を取得し、POSTで回答を記録します。回答POSTには対象ID、現在の内容ハッシュ、担当者、記録者、状態、回答、根拠とローカルトークンが必要です。CSVは `/handoff.csv` です。

## 実機導入の順序

1. 製品名・版・ブラウザかWindowsアプリか・対象PCを確定します。現セッションはブラウザ操作のみ有効です。利用者がログインした画面で会社・口座・対象月・未締め・権限を確認します。
2. 実CSV、取引先一覧、既存仕訳、受信銀行明細を読み取り、取込メニュー、必須項目、保存操作、結果の読戻しを観察します。列・セレクタ・保存順序は観察後に確定します。
3. 観察した操作を交換可能なアダプタに実装し、実行前に対象、仕訳案、取引先登録案、除外・確認待ちの一覧を提示します。現在のP1は外部実行を拒否します。
4. 利用者が承認した対象で、まず少数の取引先登録・仕訳取込と計上を実機確認します。操作意図を保存してから書き込み、実際の結果を取得し、全比較項目が一意に一致した時だけ完了を確定します。登録の完了と仕訳の完了は別々に保存します。
5. 判断できない明細は理由と確認事項を残して保留します。保存結果不明・ログイン切れ・誤会社・締め状態不明・取得失敗では該当操作を止めます。0件・複数一致・通信断で同じ書込みを再送しません。
6. 人が回答した後は最新マスタ・既存仕訳・受信明細・対象会社と月・保存結果を再照合し、必要な明細を再承認してから再開します。中断、再起動、保存後の通信断、手動計上との重複を実機で検証します。

現時点で実TKC画面、実データの取込、実際の登録・計上・保存結果照合はいずれも0件です。模擬試験で確認した範囲は [受入検証](acceptance.md)、残る実機手順は [次の実機検証](next-live-validation.md) に記載しています。

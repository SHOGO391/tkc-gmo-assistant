# 構成と制約

TypeScript / Node.js、Express、Node.js組込みSQLite、Playwrightで構成します。画面はローカルのHTML / CSS / JavaScriptです。会計案の生成は外部AI・Jevを必要としません。

```text
Browser (127.0.0.1)
  -> Express API
      -> Store / SQLite WAL
          -> original CSV bytes + SHA-256
          -> sources / sightings / transactions
          -> master snapshots / aliases / registration tasks
          -> rules / approved plans / audit / operation states
      -> TkcReadAdapter (default: unconnected)
          -> observed screen adapter (requires actual screen contract)
```

## 原本と明細

`sources` は原本単位、`sightings` は原本上の物理行と処理明細の対応、`tx` は処理明細です。同じ取引が複数原本に現れても、それぞれの原本と行位置を保持できます。原本はSHA-256名で書き換えずに保存し、ダウンロード時もハッシュを検証します。

会社・口座・実 / 模擬区分で照合範囲を分けます。同じ原本・同じ読取り条件・同じ期間は、IDなしでも原本上の行を再利用します。別原本の重複は銀行IDと日付・方向・金額・摘要・名義・残高を比較します。同じIDで内容が異なる場合は両方残して要確認にします。

日付・金額・摘要等のフィンガープリントは曖昧性の検出にだけ使います。一意キーにはしません。IDがない同一内容を自動削除せず、別IDの同日同額を別取引として保持します。

日付はローカルの日付文字列、金額は安全に表せる整数円、コード・法人番号・登録番号は文字列で保存します。不正行は原本と一緒に保持し、解析できない金額を0円の正しい取引とは扱いません。集計範囲が不完全なことを表示します。

## 取引先・仕訳・承認

名称正規化はNFKC・空白除去等による候補提示です。法人の同一性を保証しません。既存先の確定は取引先一覧と、確認者・根拠付きの確認に基づきます。確認済み別名は会社・口座・実 / 模擬区分に限定し、対象マスタの項目変更で再確認に戻します。

新規登録案は会社・実 / 模擬区分・確認済み法人番号で集約します。名称・所在地・番号それぞれに出典が必要です。コードや出典付き内容が既存案と違う場合は拒否し、同名だからという理由で統合しません。

仕訳ルールは取引先コード・入出金方向・摘要・銀行口座・任意の金額条件、科目・税区分、版、確認者、根拠を持ちます。該当ルールが0件または複数なら要確認です。複合・分割仕訳を表す配列構造は用意していますが、P1では明示された単一行ルールだけを扱います。

承認計画はID・ハッシュ・会社口座期間・確認者・時刻・明細の値・行ハッシュ・登録案参照・ルール根拠を保持します。承認後の行または根拠の変更で、その行だけ無効になります。マスタ取得時刻が変わっただけでは無関係な承認を無効にしません。

## 状態と再開

登録タスクの `registrationState` と明細の `journalState` は別です。P1の通常操作では両方 `not-sent` のままです。プレビュー承認やアプリ内対象外判断をTKCの登録済み・計上済み・対象外状態として保存しません。

SQLiteのトランザクションとWALでジョブ・判断・承認・履歴・中断状態を保存します。画面とJSONレポートの履歴は最新200件で、DBでは全履歴を保持します。再開時にアダプタの観察結果を記録します。未接続でもローカル確認は再開できますが、外部書込みには進めません。

`operations` は将来の外部処理履歴の保存先です。P1は外部操作を作りません。`reconciliation.ts` の全項目照合と再送拒否は純粋関数としてのみ検証しています。P2では送信前の意図保存、実読戻し、照合結果のDB反映を追加する必要があります。

## アダプタと未確認事項

`TkcReadAdapter` は読取り観察だけを公開し、TKC書込みメソッドはありません。実画面契約を渡す `PlaywrightReadAdapter` は交換可能です。模擬DOMテストのセレクタはTKC用のセレクタではありません。

実TKCのCSV出力仕様、取引先登録、受信明細操作、既存仕訳取得、確定コード取得、保存結果読戻しは未実装です。JSONレポートはローカル照合資料で、TKCインポート形式ではありません。

## ローカル利用とバックアップ

サーバーは127.0.0.1限定で、Host / Originを確認し、変更APIに起動ごとのローカルトークンとJSONを要求します。画面へCSV値を表示するときは `textContent` を使います。P1は単一利用者・単一サーバーでの利用を想定します。OS上で同じユーザー権限を持つプロセスからのデータ読取りを隔離する仕組みではありません。

バックアップはSQLiteのバックアップAPIによるスナップショット、原本、ハッシュ付きマニフェストを保存します。復元はハッシュ確認後に新しいフォルダへ行い、全ジョブを中断し、結果不明を保持します。P2では復元後にTKC側との結果照合が必要です。

`data/`・`backups/`・`private/`・`observations/`・テスト結果・DB・DOCX等はGit対象外です。独自の保存先を使う場合は、リポジトリ外を指定してください。業務CSVや照合レポートを別名・別フォルダでGitに追加しないでください。

# GMO × TKC 会計入力アシスト

GMO入出金CSVとTKC取引先一覧をローカルで照合し、新規取引先の登録案・仕訳案・要確認事項をまとめる **P1プレビュー版** です。添付の要件定義書 v0.1 に基づいて実装しました。

**TKCへの登録・計上は行いません。** 承認はプレビューの内容確認です。取引先登録と仕訳計上の状態は別々に保存し、実画面・既存仕訳・受信明細・保存結果が未確認なら「不明」のまま扱います。

2026-10-09時点で、模擬データを使ったローカル動作と人への引継ぎを確認しました。実TKC画面・利用者のGMO CSV・実取引先一覧は未確認です。P0の実機調査は継続中で、作業時間の削減率はまだ測定していません。

導入目標は、Computer Useで取込み・新規先登録・仕訳計上を進め、判断できない明細を人へ引き継ぐ運用です。現在はその前段のプレビューと引継ぎまで実装しています。**実TKCを操作する自動実行機能は未実装**です。実画面に接続して操作と保存結果の読戻しを確認する必要があります。[引継ぎの使い方と実機導入の条件](docs/human-handoff.md)

## 起動

Node.js 24以上、npmを使用します。WindowsではPowerShellで実行してください。利用者のTKCは別のMacのブラウザで動作しているため、導入先はそのMacです。[Macの起動・引継ぎ手順](docs/mac-setup.md)を用意しました。現在のローカル検証環境はWindows / Node.js 25.2.1です。

Mac用の配布ZIPは、展開して `Start-Mac.command` をダブルクリックすると起動します。コンパイル済みコードを同梱し、Node.jsがない場合は公式の24.21.0をSHA-256検証後に使用します。初回は依存パッケージのダウンロードにインターネットが必要です。TKC接続や登録・計上は開始しません。配布物はGitHub Actionsの成功した実行のArtifactsにある `tkc-gmo-assistant-mac` から取得できます。

```powershell
git clone https://github.com/SHOGO391/tkc-gmo-assistant.git
Set-Location tkc-gmo-assistant
npm ci
npm run dev
```

ブラウザで **http://127.0.0.1:4317** を開き、「模擬データで試す」を押します。10件の明細と模擬取引先一覧が作成されます。繰り返し押しても、練習用の会社を分けて作成します。

ビルド後の起動もできます。

```powershell
npm run build
npm start
```

起動準備の診断は `npm run doctor -- --json` です。業務DBは開かず、Node.js・SQLiteのメモリ上の動作・依存パッケージ・保存先への一時ファイル作成を確認します。診断成功はTKC実接続の確認にはなりません。配布ZIPの作成は `npm run bundle:mac`、配布物の検証は `npm run verify:mac-bundle` を使います。開発側のZIP作成にはPythonが必要ですが、ZIPを使うMacには不要です。

ポート・保存先を変更する場合は環境変数を指定します。`.env.example` は記入例で、アプリは `.env` を自動読込みしません。

```powershell
$env:PORT = '4317'
$env:DATA_DIR = 'C:/Users/YourName/tkc-gmo-local-data'
npm run dev
```

サーバーは `127.0.0.1` で待ち受けます。既定の保存先は起動ディレクトリの `data/` です。DB・CSV・照合レポートには業務情報が含まれるため、PC内のアクセス権で管理してください。

## できること

| 機能 | P1の動作 |
|---|---|
| GMO CSV取込み | UTF-8 / Shift_JIS、ヘッダー行・列対応を利用者が指定。原本のバイト列、SHA-256、取得日時、会社・口座・期間、物理行位置を保持 |
| TKC一覧との照合 | 一覧の列対応と出典・取得日時・確認者を保存。名前やカナの一致は候補として提示し、根拠を入力して既存コードを確認 |
| 新規先の集約 | 正式名称・所在地・13桁の法人番号と各出典を入力。同じ会社・法人番号の明細を1つの登録案にまとめ、共有コードを使用 |
| 仕訳案 | 取引先・入出金方向・摘要・口座・任意の金額条件に対する、根拠付きの確認済みルールから作成。科目・税区分を入出金方向だけで推定しない |
| 確認画面 | 明細、登録案、仕訳案、要確認事項、元CSVの位置、操作履歴、状態別件数・金額、JSON照合レポート |
| 人への引継ぎ | 止まった理由、原本の行とハッシュ、登録・仕訳の別状態、確認項目、再開条件、担当者・回答・根拠を保存。CSVと詳細JSONを出力。回答だけでは完了にせず、内容変更時は回答を再確認待ちに戻す |
| 中断・再開 | SQLiteに保存。再起動しても明細・判断・承認・中断状態を保持。中断中の明細変更を拒否。引継ぎ回答の記録は可能 |
| 重複管理 | 同一原本は追加しない。重複期間は銀行IDと内容を照合。別IDの同日同額は保持。IDのない同一内容・IDと内容の矛盾は要確認として保持 |
| 承認 | 計画ID・ハッシュ・確認者・時刻・行ごとの根拠を保存。変更された行の承認だけを無効化 |
| バックアップ | SQLiteのスナップショットとCSV原本を保存。ハッシュ検証後に新しいディレクトリへ復元し、全ジョブを中断状態にする |

CSVの仕様は固定していません。日付は `YYYY-MM-DD` / `YYYY/M/D`、金額は円単位の整数、入金・出金は別列を扱います。マイナス金額、両列への金額、不正日付、期間外、非JPY、不正な列数は確認対象です。不正なデータ行も原本と紐付けて保持します。ヘッダー重複や壊れたCSV構文など、ファイル全体を解釈できない場合は取込みを拒否します。1ファイル10MB・50,000行までです。

## 模擬データで試す流れ

1. 最初の明細は、模擬請求書による既存先照合と模擬仕訳ルールを設定済みです。選択して「プレビューを承認」で状態の保存を確認できます。
2. 2・3行目を選択し「新規先を集約」を押します。模擬の正式名称・所在地・法人番号 `1000000000003`、候補コード `0003`、各出典と確認者を入力します。「取引先登録案」に関連明細2件の登録案が1つ表示されます。
3. 新規先に仕訳案を作る場合は、1明細を選択して「仕訳ルール」で科目・税区分・根拠を確認します。登録案の作成だけでは仕訳は確定しません。
4. 同日同額の別ID、IDなしの同一内容、手数料・分割の未確認、不正金額、自己口座振替を確認します。判断できない明細は保留します。
5. 「中断」後にブラウザを再読込みし、状態が残ることを確認します。「再開」はローカル確認作業の再開です。

実データでは「新しい月を開始」から会社・口座・同一月内の期間・実データ区分を指定し、GMO CSVとTKC一覧を取り込みます。列の意味は実際の出力内容を確認して選択してください。原本はExcel等で再保存せず、そのまま取り込みます。

## バックアップと復元

同じデータを使う他のサーバー・CLIの変更操作を止めてから実行します。CSVとDBをGitに入れず、バックアップもPC内で管理します。

```powershell
npm run backup -- C:/Users/YourName/tkc-gmo-backup-20261008
npm run cli -- restore C:/Users/YourName/tkc-gmo-backup-20261008 C:/Users/YourName/tkc-gmo-restored-20261008
$env:DATA_DIR = 'C:/Users/YourName/tkc-gmo-restored-20261008'
npm run dev
```

保存先・復元先は新しいディレクトリが必要です。復元は稼働中のデータを置換しません。破損したバックアップは拒否します。復元後は全ジョブが中断され、「保存結果不明」は保持されます。P2で書込みを追加する際も、実TKCの結果照合前に再送してはいけません。

CLIには `get_job_status`、`plan_job`、`pause_job`、`resume_job`、`reconcile_job` を用意しています。`execute_plan` は常に拒否します。`reconcile_job` は現在は未接続状態を記録するだけで、実TKCの結果を照合できません。

```powershell
npm run cli -- get_job_status JOB_ID
npm run cli -- pause_job JOB_ID
npm run cli -- resume_job JOB_ID
```

`plan_job JOB_ID approval.json` のJSONは `{ "txIds": ["TX_ID"], "actor": "reviewer" }` です。承認前にすべての要確認事項を解消する必要があります。出力には業務情報が含まれます。

## 公開版のセキュリティとライセンス

このプレビューは実TKCへの書込みを行いません。実データのCSV・DB・バックアップ・引継ぎ出力はGitや公開Issueへ添付しないでください。

`DATA_DIR` にはアプリ専用のディレクトリを指定してください。macOS/Linuxでは起動時に専用ディレクトリを0700、DB・原本を0600へ制限し、既存の広い権限も修正します。バックアップ・復元先と引継ぎCSVにも同じ保護を適用します。Windowsではこれらのモード値だけでは他ユーザーを排除できないため、本人だけにアクセスを許可したユーザープロファイル配下とNTFSアクセス権を使用してください。同じOSアカウントの別プロセスからのアクセスや暗号化には対応していません。
